# mjml-rb 0.6.0 — 2026-10-16

`mjml-rb` 0.6.0 targets MJML 5.4.1. The gem version is independent of the
upstream MJML version. Compilation remains synchronous and pure Ruby;
Node.js/npm is used only for development reference checks.

Requires Ruby >= 3.3, `css_parser` >= 1.17 and < 4, and Nokogiri >= 1.13.
The CI matrix covers `css_parser` 1.21, 2.x and 3.x across Ruby 3.3, 3.4 and 4.0,
plus a pinned `mjml@5.4.1` reference job.

## Upgrade changes

- `mj-include` is disabled by default, including in strict validation. Enable
  it with `ignore_includes: false` and a `file_path` for the template's directory,
  or use CLI `--config.allowIncludes`. Only the canonical template root and
  explicit `include_path` roots are readable; escapes and absolute paths are denied.
- `mj-body` owns HTML `<body>`, including `id`, `css-class`, background styling
  and the preview. Update CSS selectors that expected the class on the inner
  article. Background painting below short emails can change in browser previews.
- `minify` wins over `beautify`. Source comments can be removed while preserving
  Outlook conditionals, and raw content and significant whitespace are protected.
  Formatting and entity spelling can differ from previous releases.
- Options accept snake_case and upstream camelCase aliases; conflicting aliases
  raise errors. JSON config options require `use_mjml_config_options: true`.

## Improvements

- Responsive section gutters, social icon borders, string border radii, and
  v5 hero and accordion behavior.
- Correct mixed column widths, raw siblings, social HTML, numeric image width,
  CSS include ordering, and shared component registration metadata.
- CLI validation without rendering or output files; watch mode follows enabled
  recursive includes, including deletion, recreation and graph changes.
- Support for `css_parser` 3.x, with usage, migration and compatibility documents
  included in the packaged gem.

## Validation and scope

Maintainer-reported downstream validation covered eight booking-mailer actions,
eleven representative scenarios, nine locales and desktop/mobile widths. All
198 exact Chrome screenshot comparisons at commit `90f646e` with `css_parser`
3.3.0 matched the prior 0.6.0 / `css_parser` 2.2.0 run at `313ad6a`. All 198 master
control captures also matched their previous run.

Against the downstream application's 0.5.2 baseline, 185 comparisons were
pixel-identical, eleven differed only in the background below short desktop
emails, and two restored a missing space in the Turkish KYC email. A white
HTML-root background applied only in the browser harness eliminated all eleven
background differences exactly; no footer markup change was needed. There were
no rendering errors, missing images or unstable captures. All 198 generated HTML
documents had balanced tags, and all 32 focused downstream specs passed.

These are representative Chrome renders, not email-client certification.
Customer screenshots remain private and public examples use synthetic content.
The strict XML parser, conservative formatter and custom CSS inliner retain
documented differences from upstream. Unsupported minifier and Juice options
fail explicitly; JavaScript config and component packages are unsupported.

The packaged `docs/MIGRATING_TO_V5.md` and `docs/PARITY_AUDIT.md` contain the full
migration details and compatibility limits.
